# 这帮人脑子好像都有问题 · 成人荒诞喜剧

[返回首页](<../README.md>) · [剧本格式与安全限制](<../docs/adventure-format.md>) · [数据恢复](<../docs/development-and-recovery.md#本地数据与恢复>)

玩家与矮人战士布兰、半身人盗贼莱拉、修女牧师伊琳组成四人小队，深夜潜入黑蔷薇城堡，完成一份听起来十分神秘的委托。古堡、低语、秘密都齐了，唯一的问题是：这四个人里，好像没有一个脑子是正常的。

**内容提示：面向成年玩家，含粗口、黑色幽默、性暗示与权力讽刺；不是露骨色情。** NPC 各有底线与选择权，亲密度不代表服从或同意。

## 路线与角色

参考路线从公爵书房出发，经过城门、长廊、庭院与餐厅，进入可休整的礼拜间，再穿过祭衣间与楼梯面对城堡主人；也可以交涉、调查、绕行或拒绝，不要求逐拍走完。六场简化遭遇保留兼容数值结构，击败默认是制服或停机而非杀死，失败仍然失败。三名队友有正常的基础职业能力，成功可以来自本领，不是每次都靠事故。

本世界的公开常识：**真正的吸血鬼晒太阳不会死，只会暂时变丑、声音嘶哑；严重曝晒可能持续半年。** 但传闻、衣着和饮料并不能证明某个人的种族。人物真实身份与各自的误解由主持人按现场信息演绎，不在这里剧透。

布兰严肃嘴硬但懂斧盾与打铁，伊琳会用神学解释肌肉迷恋也会认真救护，莱拉爱逞帅也懂锁具和潜行。性格缺点是有时出现的笑点，不是每轮降智的指令。成年男性玩家可能成为布兰的暗恋对象，伊琳喜欢布兰，莱拉喜欢伊琳；这不是自动成功的恋爱配对，玩家身份和回应始终由用户定义。

先听公爵本人说明委托，你可以调查、提问、接下或拒绝；剧情行动由玩家决定。拒绝委托后仍有可互动的告别场景，不强制告解、亲密接触或撮合恋情。

## 可以尝试

- 先与三名队友交谈，弄清他们各自关心什么，再决定怎样处理公爵的委托。
- 自由描述普通交谈、等待、取物、交易或移动；主持人直接叙述完成、拒绝或具体条件，不要求动作工具先批准。背包、位置和养成由幕后整理已提交正文，面板滞后不代表事情没发生。
- 确有必要时使用剧本检定和简单 d20 遭遇规则，承接真实骰点和生命变化，不由旁白保送必胜或连续代打；普通互动不要全部变成检定，撤退不会重置敌人剩余 HP。
- 观察队友如何根据亲历事件协助、拒绝或改变关系。主持人演绎全部人物，[幕后养成与信息边界](<../docs/npc-autonomy.md>)保留每人的独立积累，不要求独立 agent 逐个审批。具体模型表现不作通过承诺。
- 抵达结局后可回顾，但不能继续改变已结束的游戏。NPC 亲密度、记忆、知情只属于当前存档，不写入全局角色库。

这是简化短篇，不是完整 D&D 5e：d20 + 固定修正，自然 1 失败、自然 20 成功，暴击双倍固定伤害。真实在线模型和 GUI 完整游玩仍需另行验收。

## 修改、打包与导入

[下载/导入示例 ZIP](<curtain-castle.zip>) · [剧本配置](<curtain-castle/adventure.yaml>) · [包清单](<curtain-castle/manifest.yaml>)

新版剧本标识为 `curtain-castle@2.1.1`，只用于新开局。旧存档仍使用原版本冻结快照，导入新版不会迁移、改写或重开旧局。修改示例后由维护者在项目根目录统一执行：

```sh
npm run build:demo
```

构建脚本生成上面的示例 ZIP，并通过正式解析器验证。ZIP 根级清单引用 adventure、角色 YAML/JSON 以及可选静态图片，不套外层目录。字段、5 MiB 压缩/20 MiB 展开/128 项等限额、禁止内容、版本幂等和快照规则集中见[剧本格式](<../docs/adventure-format.md>)。

内置只带这一个示例剧本。旧的灰石矿洞已移出 `demo/`，只作为[回归 fixture](<../tests/fixtures/graystone/manifest.yaml>)保留，不随包发布；已有灰石存档继续使用自己的冻结快照，不受影响。

内置初始化可通过受信任的 `store.importDirectory()` 读取示例目录，但不要向远端用户暴露此文件系统路径接口。锁、原子写盘、坏档处理与备份步骤见[开发与恢复](<../docs/development-and-recovery.md>)；不要删除存档或未知锁来跳过错误。
