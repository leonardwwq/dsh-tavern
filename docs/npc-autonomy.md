# NPC 自主性与幕后养成

[返回首页](<../README.md>) · [剧本格式](<adventure-format.md>) · [作者写作约定](<adventure-framework-v2.md>) · [开发与恢复](<development-and-recovery.md>)

## 一个主持人，多个人物

当前冒险由主持 LLM 同时演绎旁白和全部 NPC。**不再要求独立 spawn、逐人发言工具或动作审批**。普通交谈、等待、交付、拾取、移动和人物间互动直接在正文中推进；没有真正冲突时，不因“还没过后台工具”反复准备、清点和征求确认。

人物自主不等于多 agent 的调用次数，而是角色有自己的利益、知识、性格、职业能力和经历：

- 可以合作、反对、欺骗、拒绝、讨价还价、离队或改变立场；不必须迎合玩家，也不自动全员反对。
- 好感不是服从或同意按钮，低好感不等于坏人。没有“好感低于 X 自动背叛”或“说满 N 次就原谅”的阈值。
- 角色缺点有具体触发处境，不等于每时每刻没有常识。职业本领可以正常发挥，成功不必全部靠事故；危急时先处理当前危险，不重讲无关旧怨。
- 感情、原谅、牺牲和结局不固定。玩家决定自己的身份与回应，人物按实际相处更新看法，不靠既定配对强迫恋爱。
- 不要求每个角色轮流对同一问题表态。通过动作、先后接话和具体后果体现区别，普通互动不必都变成检定。

## 主持人可知，不代表人物全知

主持人读取作者资料、完整角色卡及各人的本局 cultivation 积累，以维持长程连续性。这些是内部叙事参考，不直接作为公开面板内容，也不要求主持人向玩家公布。

每个角色仍只知道自己亲历、被告知或合理推断的信息。幕后整理按正文发生时的场景、audience 与目标场景实际出场者筛选；新到场的人不自动知道此前交易或私下对话，角色 A 的私有经历不复制给角色 B。作者真相不能无缘无故变成全员台词，错误信念也可被新证据修正。

不要为了隐藏反转强迫人物撒谎，也不要把出口名、后续场景参考或幕后动机当成玩家已经知道的事实。静态公开投影与语义保密不同：模型可能出错，仍需真实试玩检查是否剧透、互相读心或替玩家决定。

## 正文与养成的职责分离

```text
玩家自由表达 → 主持人叙述实际进展、人物言行和后果
→ 提交的完整正文进入事件日志
→ 后台记录器提取本轮事实，幂等整理物品、位置及重要事件
→ 给每个相关 NPC 生成仅属于自己的经历事件
→ cultivation 更新该存档内角色的记忆、关系和判断
```

记录器不能续写、审核或批准正文，也不靠正则关键词判断自然语言行动是否获准。它只记录真正发生的事：愿望、拒绝、附加条件与未来计划不等于交付成功；物品记录确认的当前总量，未提及物品不清空。

每个 NPC 的 `npcText` 只含本人的实际言语；`observations` 是其亲历事实摘要，不是整段正文。`playerText` 仅在该角色实际感知对应玩家输入时使用。`context` 仅含该 NPC 已筛选的亲历摘要，不能把其他人的私密事件归给玩家，也不能批量灌入全篇旁白。

后台格式失败不部分改档，失败或延迟不是角色沉默、拒绝或事情未发生。下一轮应承接已提交正文，不重复发钱或重演交易；背包和关系面板可能晚于正文更新，技术提示不变成剧情中的等待或借口。后台成功只意味着完成记录，不是为主持人批准行动。

## 规则数值与叙事后果

声明的检定、战斗及安全休整仍使用对应规则工具，不能伪造骰点、HP、伤害或重复奖励。幕后记录器不修改这些规则数值，也不写 flags 或检定结果。普通位置和交易不需要额外行动工具批准。

正文可明确描述角色离队、失踪或可见伤势，后台整理相应人物状态；未提及的状态保留。不因为离队自动跑一场独立 agent 冒险，也不靠后台表格擅自制造营救、和解或归队。后续寻找、拒绝或回归仍应有合理的故事因果，不能当成重置关系的按钮。

旧系统中的自主决策、协助/干扰/挡伤、离队工具与事件结构可为旧数据及底层兼容保留，但不是当前主持的强制调用链。旧记录中的“行动意向、尚待裁定”也不自动变成已经完成的事实。

## 存档与验收

角色养成只写本局存档，不写全局角色库；导入新剧本版本不重写旧存档快照，也不清空旧关系与记忆。内置 `curtain-castle@2.1.1` 只供新开局使用。

自动测试可验证来源检查、幂等、原子失败和各 NPC 事件隔离；不能保证人物永远符合性格、模型绝不剧透或关系发展达到人类水平。自然度、长期连续性、实际延迟和完整 GUI 游玩仍需真实模型与原页面验证，不能以独立 agent 数量或测试通过冒充体验保证。
